# V4 - универсальный пайплайн добавления и обновления документов

## Назначение

В V2 корпус собирался вручную: глава за главой готовились исправленные Markdown-файлы (data/extracted), затем отдельным импортёром переводились в чанки и сливались в `V2/data/chunked_merged_manual`. В V4 эта работа должна выполняться одним пайплайном: новый или изменённый документ проходит разбор, чанкинг и индексацию без ручной сборки корпуса.

Решение о переносе задачи принято при планировании V3: V3 отведён гибридному поиску (BM25 + E5 + RRF + реранкер BGE), а пайплайн документов вынесен в V4.

## Что должен уметь пайплайн

1. Принимать документ (PDF, DOCX, Markdown) и определять, новый он или обновлённая версия уже загруженного.
2. Разбирать структуру: разделы, главы, пункты с номерами, таблицы, рисунки, формулы.
3. Нарезать текст на чанки по правилам V2: граница чанка совпадает с пунктом, таблицы и формулы не разрываются, ресурсы (изображения) сохраняются.
4. Записывать происхождение каждого чанка: исходный файл, версия, номер пункта, страница.
5. Обновлять индекс точечно: удалять чанки старой версии документа и добавлять новые, не пересобирая весь корпус.
6. Обновлять все коллекции, которые используются поиском (базовую, e5, rerank, изображения CLIP).
7. Вести журнал загрузки: что добавлено, что заменено, что не распознано.
8. Проверять результат: число пунктов до и после, отсутствие потерянных таблиц и формул, совпадение номеров пунктов с оглавлением.

## Ограничения

- Исходные документы и официальный текст ПУЭ не меняются.
- Корпус V2 (`chunked_merged_manual`) остаётся эталоном для сравнения: пайплайн V4 на тех же главах должен давать не хуже по полноте и метрикам поиска.
- Конфиги с device cuda и clip_device cuda берутся с Drive.

## Проверка

- Прогон пайплайна на главах 1.1-1.9 и сравнение чанков с `chunked_merged_manual`.
- Повторный расчёт метрик поиска на наборе split (720 вопросов) и сравнение с V2.
- Проверка обновления: замена одной главы новой версией без пересборки остальных.

## Структура папки

- `docs/` - описание, решения, инструкции.
- `scripts/` - код пайплайна (создаётся при начале работ).
