# V2: исключение архива из рабочего корпуса

Это исправление существующего V2, не V3 и не новая система импорта документов.

## Что исправлено

Общий загрузчик `V2/scripts/prepare_retrieval_qrels.py` раньше рекурсивно читал
все JSONL, включая исходные/заменённые варианты внутри `_audit`.
Теперь `_audit` исключается до обхода вложенных папок (без учёта регистра).
Его JSONL не попадают в корпус, манифест, индексацию и кандидаты qrels.
Обычные вложенные папки рабочих документов продолжают поддерживаться.
Прямое использование самого `_audit` как корпуса и ссылки на его JSONL отклоняются.

Индексация, поиск и проверка V2 используют этот же загрузчик через
`src/retrieval_eval/corpus_manifest.py`, поэтому исправление действует не только
на подготовку qrels. Архивы не удаляются и не меняются.

## Установка

Сначала сохраните резервную копию своего `V2/scripts/prepare_retrieval_qrels.py`
вне папки с рабочими чанками. Распакуйте ZIP в корень проекта, разрешив замену
этого файла. Имена внутри ZIP обычные, версия есть только в имени архива.

Другие производственные файлы этого комплекта новые:
`V2/scripts/configure_manual_corpus.py`, тесты и эта инструкция.
Старые `scripts/convert_chunked_V0_to_V2/convert.py` и новый Markdown-импортёр
из предыдущего архива не затрагиваются. Перезапускать импорт/merge не надо.

## Переключение уже подготовленного корпуса без ручного копирования

Из корня проекта выполните:

```powershell
python V2/scripts/configure_manual_corpus.py
python V2/scripts/run_pipeline.py validate --corpus-only --config V2/configs/pipeline_manual_merged.json
```

Первая команда читает ваш `V2/configs/pipeline_manual.json` и создаёт отдельный
`V2/configs/pipeline_manual_merged.json`. Меняется ТОЛЬКО `paths.chunks`, на
`V2/data/chunked_merged_manual`. Модели, вопросы, разрешённые коллекции и прочие
параметры остаются вашими. Существующие конфиги не перезаписываются.

Ожидаемые поля первого вывода: `documents_jsonl: 46`, `chunks: 3146`,
`audit_excluded: true`, `database_write_performed: false`.

Если исходным конфигом служит основной pipeline.json, задайте это явно:

```powershell
python V2/scripts/configure_manual_corpus.py --from-config V2/configs/pipeline.json
```

Если новый конфиг уже существует, программа останавливается, не заменяя его.
Для повторного запуска можно указать другое имя через `--output-config`, после
чего использовать это имя с `run_pipeline.py --config`.

Ранее сделанную копию `V2/data/chunked_active_manual` можно пока оставить.
Новый конфиг её не использует. Ничего автоматически не удаляется.
Для следующих шагов всегда указывайте `--config V2/configs/pipeline_manual_merged.json`:
основной pipeline.json намеренно не переключается скрыто.

## Предупреждения и следующие шаги

На проверочном корпусе validation дал 3451 предупреждение и 0 ошибок:
3146 `ownership_not_manually_accepted` и 305 `no_unambiguous_own_clause`.
Первое означает отсутствие формального признака `owner_review_status=reviewed`,
а не 3146 доказанных ошибок. Второе — блоки без однозначного собственного пункта,
включая контекст/заголовки; по одному этому признаку считать их бракованными нельзя.
Исправление загрузчика не подменяет содержательную проверку и не ставит reviewed.

Кандидаты привязок тестовых вопросов к новым чанкам создаются отдельно:

```powershell
python V2/scripts/prepare_retrieval_qrels.py generate --project-root . --chunks V2/data/chunked_merged_manual --output V2/data/rag_eval_questions/retrieval_qrels.candidates.manual_merged.json
```

Это НЕ готовый эталон qrels и не оценка качества поиска. Кандидаты нужно проверить;
их нельзя принять переименованием файла. Уже существующие qrels или кандидаты,
созданные по пути `chunked_active_manual`, не считаются совместимыми автоматически:
путь входит в манифест корпуса. Перед поиском/оценкой также нужны отдельные новые
имена коллекций и совместимые qrels. Этот архив НЕ загружает базу и НЕ выполняет поиск.

## Проверки комплекта

```powershell
python V2/scripts/tests/test_audit_exclusion.py
python V2/scripts/prepare_retrieval_qrels.py self-test
```

18 новых тестов и 2 встроенных теста qrels прошли. Проверены исключение архива,
некорректный JSON/повторы в архиве, сохранение обычных вложенных документов,
ошибки активных JSONL, symlink в архив, запрет выбрать архив напрямую,
неизменность исходного конфига и отказ от перезаписи нового.

На изолированной копии фактического корпуса напрямую из `chunked_merged_manual`:
46 активных JSONL, 3146 чанков, 0 ошибок validation; generate создал 925 пар
кандидатов для 268 вопросов, без вопросов с нулём кандидатов. Это не доказательство
полноты ответов. Все 1388 файлов корпуса и архива проверялись на неизменность
по SHA-256 (точное число также записано в verification.json).

Существующие 33 теста retrieval также сравнивались до/после: в обоих случаях
32 прошли, один `test_evaluate_no_db` упал из-за старой синтетической выдачи без
`resources_mode`, которую текущий run_pipeline.py требует. Новых регрессий
этого набора не выявлено. Этот отдельный конфликт тестовой фикстуры исправление
архива не меняет. Для запуска набора его исходный конфиг в тестовой копии был
согласован с ожидаемым фикстурой `data/chunked`; пользовательские конфиги не менялись.

Фактическая среда — Linux / Python 3.13.5; синтаксис проверен с грамматикой Python 3.9.
Реальные Windows/Python 3.9, модели и Milvus в этой проверке не запускались.
Журналы и результаты лежат рядом с инструкцией.
