# V2 — исправления 1_5

Это обновление существующего комплекта V2, а не полный проект. Конфигурации, вопросы, qrels, модели, исходники raw и старый корпус data/chunked в архив не включены и не заменяются.

## Установка

1. Сохраните резервную копию папок `V2/src` и `V2/scripts`. Архив заменяет только перечисленные в `Состав.json` файлы; весь проект переустанавливать не нужно. Поставка включает прежние исправления извлечения и заменяет поставку 1_4.
2. Распакуйте архив **в корень проекта** `X:\Учеба_УИИ\Итоговы_Проект`. В архиве уже есть верхняя папка `V2`: не распаковывайте его внутрь существующей `V2`, иначе получится `V2/V2`.
3. Объедините папки и замените только одноимённые файлы из архива. Не удаляйте существующую папку V2 целиком. `pipeline.json` и настройки CUDA сохраняются.
4. Для нового корпуса нужна **пустая** папка `V2/data/chunked`. Если она не пуста, ничего не удаляйте вслепую: скрипт откажется перезаписывать корпус. Сначала сохраните существующие результаты отдельно.
5. В вашем `V2/configs/pipeline.json` путь `paths.chunks` уже должен быть `V2/data/chunked`. Скрипт его не редактирует. Общий загрузчик V2 также требует существования папки активных чанков и файла вопросов, даже без загрузки моделей.

Извлечение `documents_20261108_152653_863842` можно использовать повторно: запускать `prepare-documents` заново для этой правки не нужно.

## Запуск из корня проекта

У вас уже есть корпус от предыдущего запуска. Сначала переименуйте его в резервную папку и создайте пустую целевую. Это не удаляет старые результаты. Если какая-либо команда завершилась ошибкой, остановитесь и разберите её, не удаляя папки вслепую.

```powershell
Rename-Item -LiteralPath "V2/data/chunked" -NewName ("chunked_backup_" + (Get-Date -Format "yyyyMMdd_HHmmss_fff"))
New-Item -ItemType Directory -Path "V2/data/chunked" | Out-Null
```

Если целевая папка уже пуста, переименование не требуется. Общий загрузчик требует существующую папку, поэтому после переименования нужен `New-Item`.

Затем создайте **структурные кандидаты**, без базы и моделей:

```powershell
python V2/scripts/prepare_chunks.py
```

Скрипт сам выбирает последнее завершённое извлечение в стандартной папке `V2/results/retrieval` по времени в имени папки, не по времени изменения. Незавершённые папки пропускаются с перечислением в отчёте; повреждённый manifest последней завершённой папки вызывает ошибку, а не возврат к старым данным.

Перед нарезкой скрипт повторяет структурную проверку извлечения. При наличии `error` кандидаты не создаются. Замечания `review` не исчезают: они сохраняются в отчёте, а корпус остаётся **непринятым для финальной оценки**.

При необходимости явно выбрать извлечение:

```powershell
python V2/scripts/prepare_chunks.py --input V2/results/retrieval/documents_20261108_152653_863842
```

Затем проверьте соответствие записанных кандидатов исходному Markdown:

```powershell
python V2/scripts/check_preparation.py
```

Проверяется последний запуск подготовки. Если последний запуск завершился ошибкой и не создал `preparation.json`, проверка не подменяет его более старым успешным результатом. Для прежнего успешного отчёта можно явно задать `--report V2/results/retrieval/preparation_<дата>_<время>_<микросекунды>/preparation.json`.

Повторный запуск подготовки в непустую папку запрещён. Повторять только проверку можно: она сохраняет отдельный результат и не меняет чанки.

## Результаты

Кандидаты: `V2/data/chunked/*.chunked.jsonl`, ресурсы: `V2/data/chunked/assets/`.

Отчёты: `V2/results/retrieval/preparation_<дата>_<время>_<микросекунды>/`:

- `extraction_audit.json` — повторная сверка извлечения;
- `preparation.json` — полный состав документов, границы исходных фрагментов, ID, контексты, предупреждения;
- `console.json` — точно тот краткий JSON, который показала команда подготовки;
- `coverage_check.json` — результат отдельной проверки покрытия; при повторной проверке добавляется суффикс времени;
- `error.json` — описание ошибки подготовки, если она возникла после чтения аргументов.

Код возврата подготовки и проверки покрытия: 0 — соответствующая техническая операция прошла; 2 — ошибка. Это не код семантического одобрения. Отдельный `check_extraction.py` по-прежнему возвращает 1 при `requires_review`.

После запуска разместите на Drive новую папку отчёта с **`preparation.json` и `coverage_check.json`**, а также обновлённый `V2/data/chunked`, чтобы можно было сверить реально полученные файлы. До проверки границ и таблиц не запускайте `load`, `load-clip`, `all`, не используйте прежние qrels для финальных метрик.

## Что исправлено

В поставке 1_5 дополнительно:

- Подпись «Министр» и блок «УТВЕРЖДЕНЫ» выделяются в служебные фрагменты без номера. Заголовок следующих Правил также больше не входит в пункт 3 приказа. Разделы с римской нумерацией продолжают задавать самостоятельные контексты.
- Отдельный заголовок «Коэффициенты перегрузки», непосредственно за которым следует Markdown-таблица, начинает отдельный `table_block` с пустыми `Clause` и `ClauseKey`. Таблица вместе с примечаниями сохранена, а нормативный владелец не выдуман. Правило узкое: произвольные упоминания этой фразы в тексте не образуют границу. Это НЕ автоматическое разрешение принадлежности всех остальных таблиц корпуса.
- Из текста кандидатов удаляются только распознанные служебные маркеры прежней справочной системы. Печатные названия ГОСТ, СНиП и номера документов сохраняются. `#G01)` очищается до `1)`, а не до `)`.
- Markdown и raw не редактируются. Каждый удалённый маркер записан в `normalization_edits` соответствующего диапазона `source_spans`: начальная и конечная позиции в неизменном исходном Markdown, точный удалённый текст и вид операции. Проверка независимо разрешает только известные управляющие формы и сверяет получившийся текст с чанками.
- URL, пути Markdown-ссылок, инлайн-код и ограждённые блоки кода очистка не затрагивает. Неизвестные или численно неоднозначные формы сохраняются с предупреждением `legacy_markup_unresolved_preserved`.
- В проверенной копии остаются две числовые ссылки: `#M12291 120001242630030 …#S` в 1.7 и `#M12291 12000076223064-80#S` в 2.5. Число идентификатора склеено с печатным номером; автоматическая обрезка могла бы удалить полезные цифры. Также сохранён одиночный `#S` после заголовка в 6.1. Это 5 оставшихся токенов в 3 документах, а не 5 потерянных пунктов.
- Краткий JSON запуска дополнительно показывает `removed_control_tokens` и `unresolved_markup_tokens`. Полный журнал остаётся в `preparation.json`. Проверка понимает отчёты 1_4 и 1_5; для 1_5 отдельно подтверждает допустимость удалений.

Сохранены прежние правила:

- Нумерация ПУЭ вида `1.2.3` остаётся отдельным режимом: вложенные списки `1.` внутри такого документа не становятся владельцами пунктов.
- Для документов без трёхуровневой нумерации создаются кандидаты по одноуровневым номерам. Автоматически отличить нормативный пункт от элемента списка программа не утверждает.
- Заголовки Markdown, римские разделы и приложения образуют контексты `Scope`; при повторе или уменьшении номера создаётся новый контекст с предупреждением.
- `ClauseKey` содержит документ, контекст и номер. Одинаковые номера из разных контекстов не смешиваются. Ссылки между пунктами автоматически не разрешаются.
- Предисловия, заголовки и документы без номеров не пропускаются: сохраняются отдельными фрагментами без выдуманного номера пункта. Например, содержание получает пустой `Clause` и непринятый статус владельца.
- Состав Markdown сверяется с `extraction.json` и `source.json`. Пропавший, лишний, пустой или повторный документ вызывает ошибку, а не скрытое исключение.
- Все исходные символы входят в диапазоны разбиения; покрытие чанками сверяется после явно зарегистрированных разрешённых удалений управляющих маркеров и переписывания локальных путей ресурсов. Пустые промежутки и форматирование пробелов могут нормализоваться. Произвольные содержательные удаления не разрешаются.
- Исправлена обработка изображения внутри буквальных квадратных скобок. Локальные ресурсы копируются по хешу содержимого; отсутствующий ресурс блокирует подготовку. Интернет-ресурсы не скачиваются.
- ID не зависят от даты папки извлечения, но зависят от документа, контекста, текста и номера части. После изменения правил нарезки нужны новые проверенные qrels, а не замена контрольной суммы старых.
- Кандидаты сначала полностью проверяются и записываются во временную папку, затем переносятся в целевую. Непустой корпус никогда не перезаписывается.
- Абзац или таблица больше лимита не обрезаются и не дробятся вслепую: подготовка останавливается с указанием документа. Отдельная строка таблицы также не разрезается.

## Ограничения и оставшиеся 22 замечания

Обновление **не снимает** 17 замечаний по документам с объединёнными ячейками таблиц, 3 замечания по отсутствию буквальной нумерации `1.2.3`, одно замечание по RTF и одно по `link.md`. Это 22 замечания, а не 22 доказанно испорченных файла.

Сохранение XML таблиц и текста не доказывает правильность связи заголовков со значениями. RTF автоматически не конвертируется и не объявляется дублем DOCX. HTML и вложенные ресурсы `link.md` полностью не разобраны. Колонтитулы, автоматическая нумерация Word, формулы и неоднозначная структура сохраняют ограничения извлечения.

Ни один кандидат не помечается `reviewed`. Итог подготовки имеет `ready_for_final_scoring: false`; проверка покрытия имеет `semantic_or_visual_approval: false`. Нельзя выдавать техническое покрытие за доказанную правильность нормативных ответов.

Номер версии **1_5** добавлен только к имени архива, а не к именам устанавливаемых файлов; имена устанавливаемых файлов не имеют суффикса версии. Это версия **поставки 1_5** и нарезки `v2-markdown-scoped-1_5`. В архиве также лежат ранее исправленный SDT-экстрактор `v2-documents-2-sdt` и аудитор `extraction-audit-1.3`: их номера намеренно не переименованы без изменения алгоритма.
