# V2 — исходники 0.2 (НЕ ПРОВЕРЕНЫ)

По просьбе пользователя код этой версии не запускался, тесты и компиляция не выполнялись. Milvus, модели и пользовательский проект не затрагивались. Это поставка исходников для локального запуска, а не подтверждение работоспособности. Старые протоколы тестирования версии 0.1 к версии 0.2 не относятся.

## Что входит

Все этапы проверки поиска: конфигурация, извлечение DOCX/Markdown, ресурсы, разбиение по пунктам и частям, манифест и валидация, генератор кандидатов qrels, загрузка Milvus, текстовый поиск, CLIP-индекс, объединение RRF и rerank, сохранение выдачи, экспорт ресурсов, Hit/MRR/nDCG/покрытие, Markdown/HTML/CSV-отчёты, графики и генератор ноутбука. Добавлены CLI-входы по именам из карты V2 и PowerShell-обёртки.

Это новая самостоятельная реализация V2, не буквальная копия старых классов. Программный API — `retrieval_eval.api.RetrievalClient`; в адаптерах `multimodal_rag.py`, `e5_rag.py`, `rerank_rag.py` доступны `RAG` и `create_retriever`. Автоматическая совместимость со старым ботом не обещается. Генерация ответов, Ollama, инфраструктура и обновление дипломных отчётов остаются вне пункта 2.

## Как перенести

1. Сначала распакуйте архив в отдельную временную папку, а не поверх существующего проекта.
2. Перенесите нужные файлы в существующую `Проект/V2`, сохранив структуру. Перед заменой собственных настроек оставьте копию.
3. Прежние `data/raw` и `data/chunked` не перемещайте. Собственные вопросы, gold-архив и принятый `retrieval_qrels.json` сохраняйте в `V2/data/rag_eval_questions`. Они намеренно не включены в архив.
4. Единственный активный конфиг — `V2/configs/pipeline.json`. Соседние runtime-конфиги и model_profiles/embedding_config — справочные исходные настройки; профиль из model_profiles можно подключить явно через `model_selection.profile`. Скрытого чтения старых конфигов нет.
5. Результаты записываются в `V2/results/retrieval/<run_id>`. Старые результаты и коллекции не очищаются.

## Модели

В исходных runtime base и E5 указан один `intfloat/multilingual-e5-base`, 768; это сохранено, включая E5-префиксы. В старом base был включён автоматический подбор; здесь он намеренно не воспроизводится скрыто. Для другой base-модели явно задайте `model_selection.profile` (`rtx2060_baseline`, `mid_gpu`, `high_gpu`) или поля `modes.base`. При изменении модели нужна отдельная новая разрешённая коллекция. Нельзя называть одинаковые настройки сравнением разных моделей.

CLIP — отдельный необязательный индекс `diplom_v2_clip`; модель-адаптер `sentence-transformers/clip-ViT-B-32` (ViT-B/32). Это не обещание совпадения весов со старой open_clip-сборкой. CLIP-поиск по русским запросам требует отдельной оценки качества. Текстовая и CLIP-выдача объединяются RRF по связанным чанкам, затем применяется финальный rerank, если выбран этот режим.

По умолчанию `device=cpu`, `local_files_only=true`; модель должна уже находиться в локальном кэше. Если хотите разрешить её загрузку, измените этот флаг самостоятельно. Здесь ничего не устанавливалось и не скачивалось.

## Команды для вашего локального запуска

Все команды ниже — инструкция, не выполненные действия. Запускать из корня исходного проекта; в Linux при необходимости замените `python` на `python3`.

Подготовка отдельного окружения (если требуется):

```powershell
python -m venv V2/.venv
V2/.venv/Scripts/python.exe -m pip install -r V2/requirements.txt
```

Если используете это окружение, во всех следующих командах замените `python` на его интерпретатор. PowerShell-обёртки используют `python` из активного окружения.

Показ плана, без обращения к Milvus и моделям:

```powershell
python V2/scripts/run_pipeline.py plan --mode base
```

Проверка существующего корпуса и принятой разметки (выполните позднее по своему решению):

```powershell
python V2/scripts/run_pipeline.py validate
```

Проверка только корпуса, без принятого qrels:

```powershell
python V2/scripts/run_pipeline.py validate --corpus-only
```

Извлечение только документов, если нужно переделывать корпус:

```powershell
python V2/scripts/run_pipeline.py prepare-documents --from-raw data/raw
```

Извлечение и разбиение по пунктам:

```powershell
python V2/scripts/run_pipeline.py prepare --from-raw data/raw
```

Либо разбиение уже подготовленных Markdown (замените путь результатом извлечения):

```powershell
python V2/scripts/run_pipeline.py prepare --from-md V2/results/retrieval/documents_<run_id>
```

Подготовка требует пустой `V2/data/chunked`, не перезаписывает готовый корпус. Результат НЕ активируется автоматически: после содержательной проверки явно измените `paths.chunks`, подготовьте новую принятую разметку и укажите её в `paths.qrels`.

Генератор разметки:

```powershell
python V2/scripts/prepare_retrieval_qrels.py --help
```

Он создаёт только кандидатов; их нельзя считать утверждённым эталоном или включать в итоговую оценку. Для существующего корпуса используйте уже переданный принятый qrels.

Загрузка новой текстовой коллекции — только по явной команде:

```powershell
python V2/scripts/run_pipeline.py load --mode base --allow-db-write
python V2/scripts/run_pipeline.py load --mode e5 --allow-db-write
```

Rerank использует индекс E5, поэтому отдельная повторная загрузка в ту же коллекцию не нужна. Существующая коллекция отклоняется, а не очищается. При сбое загрузки может остаться неполная новая коллекция: она не удаляется автоматически; выберите новое имя в разрешённом списке или разберите состояние вручную.

Необязательная отдельная загрузка CLIP:

```powershell
python V2/scripts/run_pipeline.py load-clip --allow-db-write
```

Поиск без эталонных ответов в запросе:

```powershell
python V2/scripts/run_pipeline.py search --mode base
python V2/scripts/run_pipeline.py search --mode e5
python V2/scripts/run_pipeline.py search --mode rerank
```

Поиск с CLIP и фактическим экспортом ресурсов:

```powershell
python V2/scripts/run_pipeline.py search --mode rerank --with-clip --with-assets
```

Изображения/связанные ресурсы копируются рядом с выдачей, снабжаются SHA256 и связями с найденными чанками. Один CLIP-score или ссылка на картинку не считаются доказательством полного ответа. При оценке проверяются экспортированные файлы, а ресурсы учитываются только в пределах первых k результатов.

Оценка только сохранённой выдачи (замените `<run_id>` реальным именем):

```powershell
python V2/scripts/run_pipeline.py evaluate --input V2/results/retrieval/<run_id>/retrieval.json
```

Оформление метрик, без повторного поиска:

```powershell
python V2/scripts/run_pipeline.py report --input V2/results/retrieval/<run_id>/metrics.json
python V2/scripts/run_pipeline.py plot --input V2/results/retrieval/<run_id>/metrics.json
python V2/scripts/run_pipeline.py notebook --input V2/results/retrieval/<run_id>/metrics.json
```

Полный поиск и оценка по существующей совместимой коллекции:

```powershell
python V2/scripts/run_pipeline.py all --mode e5 --reuse-collection
```

Полный запуск с созданием новой коллекции (не включает скрытую переделку документов/чанков):

```powershell
python V2/scripts/run_pipeline.py all --mode base --allow-db-write
```

Подготовка корпуса и содержательное принятие qrels отделены от `all` намеренно: их нельзя автоматически объявлять принятыми. Оценка/отчёты никогда не загружают базу заново.

## Существенные ограничения исходников

- Никакой готовности к эксплуатации не заявляется: новая версия не запускалась даже в режиме `--help`, тесты не выполнялись. В архиве есть исходники тестов для вашего запуска; результатов новой версии нет.
- DOCX: текст, простые таблицы, изображения и исходные XML-структуры формул/объединённых ячеек сохраняются. OMML не превращается в выдуманную формулу. Автонумерация, сноски, колонтитулы, merged cells и полнота извлечения требуют отдельной проверки. Поддерживаются DOCX и Markdown, не произвольный PDF/DOC.
- Новый чанкер назначает структурных кандидатов владельца пункта, а не автоматически подтверждённые нормативные привязки. Границы, таблицы, условия и ссылки требуют содержательного принятия. Слишком большой неделимый блок останавливает разбиение; молчаливого обрезания нет.
- Старые чанки могут пройти техническую проверку с предупреждениями; это не исправляет их принадлежность пунктам. `--strict` блокирует такие предупреждения.
- При любой смене корпуса повторно примите затронутые qrels; нельзя просто заменить номер версии.
- API Milvus, зависимости, модели, PowerShell и интеграция на вашей машине не проверялись.
