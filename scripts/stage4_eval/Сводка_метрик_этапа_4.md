# Сводка метрик этапа 4 (RAG по ПУЭ)

Контрольный набор для всех прогонов: реестр `data/rag_eval_questions/eval_questions.json` (**300** вопросов, поле `n_questions`).  
Артефакты прогонов: каталог `scripts/stage4_eval/results/` (`retrieval/`, `generation/`).  
**Последние сохранённые числа в JSON-файлах** ниже получены при *N* = **73** (до расширения набора). После полного пересчёта на 300 вопросах значения в таблице «Факт» нужно обновить из тех же путей.

## 1. Слои оценки

| Слой | Что измеряется | Скрипт | Файл результатов |
|------|----------------|--------|------------------|
| **Retrieval** | Попадание эталонного пункта ПУЭ в top-*k* (Hit@1, Hit@3, Hit@5) | `eval_retrieval_hitk.py` | `retrieval/stage4_hitk_results.json` |
| **Generation (полный RAG)** | Цитирование пункта, опора на контекст, релевантность эталону | `eval_rag_generation.py` (`live` / `mock`) | `generation/stage4_gen_eval_results.json` |
| **Эксплуатация** | Задержка, TTFT, TPS, RPS, доступность | `eval_rag_performance.py` | `generation/stage4_performance_metrics.json` |
| **LLM-as-a-Judge** | Обоснованность, релевантность ответа, полнота контекста (оценка судьёй) | `eval_rag_llm_judge.py` | `generation/stage4_llm_judge_metrics.json` |

Запуск цепочки performance + judge: `scripts/stage4_eval/run_perf_and_judge.ps1`.

**Не рассчитывается** в текущих скриптах проекта: MRR, nDCG@k (при необходимости — отдельное расширение `eval_retrieval_hitk.py`).

## 5. Метрики LLM-as-a-Judge (`eval_rag_llm_judge.py`)

Судья: модель из `config/rag_runtime.json` (в прогоне — `qwen2.5:14b-instruct-q4_K_M`). Сводка в `summary_metrics` файла `stage4_llm_judge_metrics.json`.

| Метрика (поле JSON) | Смысл | Факт (*N*=73, 18.10.2026) |
|---------------------|--------|---------------------------|
| `faithfulness_avg` | Насколько ответ согласуется с переданным контекстом (0–1) | **0,749** |
| `answer_relevancy_avg` | Насколько ответ отвечает на вопрос (0–1) | **0,619** |
| `context_recall_avg` | Насколько контекст покрывает нужную информацию (0–1) | **0,708** |

**Ограничение методики текущего скрипта:** для каждого вопроса в судейский промпт подставляются **укороченный шаблонный контекст и ответ** (не полный trace из `eval_rag_generation.py`). Поэтому эти три числа отражают работу **контура судьи и промпта**, а не повторный разбор всех live-ответов RAG. Для оценки полного контура по заземлённости и цитированию опирайтесь на §3 (`groundedness_avg`, `citation_rate`).
