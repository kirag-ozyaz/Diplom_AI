# Опыты: улучшение retrieval (этап 4)

Два последовательных изменения поиска на том же реестре, что и базовый прогон **N = 268** (18.10.2026). Цель — сравнить Hit@k и generation live с базой: Hit@5 **81,3 %** (218 / 268).

Базу заново не считать: это **опыт 0**. Перед опытом 1 скопировать JSON результатов. Скрипты оценки перезаписывают одни и те же файлы.

Параметры Milvus (`ef`, `M`, `efConstruction`) и модель Ollama в этих прогонах не менять. Первый рычаг слабее префиксов и реранкера, второй на Hit@k не влияет.

## Опыт 1. Префиксы E5

Правится один файл: `src/preprocessing/Create_embeddings/multimodal_rag.py`.

- `_encode_text` (индексация чанков) — строка `passage: {текст}`
- `search_text` (вектор запроса) — строка `query: {вопрос}`

Префиксы ставятся парой. Только `query:` на поиске при старых векторах без `passage:` поиск ухудшит.

После правки — полная перезаливка: `src/preprocessing/Create_embeddings/load_data.py`. В `config/rag_runtime.json` уже стоит `"drop_existing": true`, коллекция пересоздастся.

Скрипты оценки не менять. Hit@k (`eval_retrieval_hitk.py`) и generation (`rag_service.answer()`) оба вызывают `search_text`.

---

## Опыт 2. Реранкер

Тот же `multimodal_rag.py`, метод `search_text`, поверх префиксов опыта 1:

1. Запрос в Milvus с limit **20**.
2. Пары (вопрос, текст чанка) через cross-encoder `BAAI/bge-reranker-v2-m3`.
3. Наружу по-прежнему **5** лучших чанков.

Тогда `scripts/stage4_eval/retrieval/eval_retrieval_hitk.py` и `src/rag/rag_service.py` получают уже переранжированный контекст. `search_limit = 5` в Hit@k не менять. Перезаливка Milvus не нужна: векторы те же, что после опыта 1.

---

## Порядок прогона

1. Скопировать JSON базы (пути ниже), пока их не затёр следующий Hit@k.
2. Внести префиксы E5 и выполнить `load_data.py`.
3. Прогнать Hit@k, затем generation live. Заполнить столбец «Опыт 1».
4. Скопировать JSON опыта 1.
5. Добавить реранкер в `search_text`. Milvus не перезаливать.
6. Снова Hit@k и generation live. Заполнить столбец «Опыт 2».
7. Скопировать JSON опыта 2.

Performance и LLM-judge для опытов 1 и 2 не обязательны. Performance не ходит в Milvus. Judge в текущем скрипте считает шаблонный контекст по `expected_clause`, а не фактическую выдачу поиска.
