# RAG V3 Pipeline - документация (Этап 5)

## 1. Назначение

V3 - гибридный поиск по ПУЭ поверх корпуса и индексов V2. Корпус, вопросы, qrels и коллекции Milvus V2 не меняются: V3 только читает их и пишет результаты в свою папку `results`.

Схема поиска: BM25 + E5 + CLIP, слияние RRF, переранжирование BGE, затем ответ Qwen2.5 со ссылками на пункты ПУЭ. LLM в поиске не участвует.

## 2. Расположение и структура папок

Папка `V3` лежит в корне проекта рядом с `V2`, структура повторяет V2:

```
<корень проекта>/
  V2/                              - код, конфигурации и данные V2 (без изменений)
  V3/
    README.md                      - этот файл
    requirements.txt               - зависимости V3
    configs/
      v3_config.json               - настройки V3
    src/
      retrieval_v3/
        hybrid_retriever.py        - гибридный поиск (класс HybridRetrieverV3)
        rag_pipeline.py            - ответ Qwen2.5 через Ollama (класс V3RAGPipeline)
    scripts/
      v3_evaluation.py             - пошаговая оценка поиска
      v3_ask.py                    - вопрос и ответ из командной строки
      run_*.ps1                    - запуск из PowerShell
      stage5_eval/
        _root.ps1                  - поиск папки V3 (Get-V3Root)
        _banner.ps1                - заголовок
      tests/
        test_v3.py                 - проверки без GPU, Milvus и Ollama
    docs/
      notebooks/                   - ноутбуки этапа 5
      *.docx                       - документы по стратегии
    results/                       - результаты оценки (создаются при запуске)
```

Если расположение другое, путь к корню задаётся в `configs/v3_config.json`, ключ `project_root` (путь от папки `configs`, по умолчанию `../..`).

## 3. Зафиксированные документы по стратегии

- Стратегия дообучения RAG-системы (Fine-Tuning зафиксирован как Plan B - резервная гипотеза).
- Пайплайн и скрипты дообучения RAG-системы (Этап 5).
- Стратегические архитектурные и практические улучшения.
- Универсальный пайплайн добавления и обновления документов перенесён в V4.

Документы лежат в `docs`.

## 4. Файлы V3

- `configs/v3_config.json` - настройки: устройство (cuda), конфигурация V2 с вопросами и qrels, глубина поиска, веса RRF, параметры BM25 и BGE.
- `src/retrieval_v3/hybrid_retriever.py` - гибридный поиск (класс `HybridRetrieverV3`).
- `src/retrieval_v3/rag_pipeline.py` - генерация ответа Qwen2.5 14B через Ollama (класс `V3RAGPipeline`, метод `ask`).
- `scripts/v3_evaluation.py` - пошаговая оценка поиска на вопросах и qrels V2.
- `scripts/v3_ask.py` - один вопрос: поиск и ответ со ссылками на пункты ПУЭ.
- `scripts/tests/test_v3.py` - проверки токенизации, BM25, RRF, окон, шагов и настроек.
- `docs/notebooks/stage5_final_pipeline_notebook.ipynb` - ноутбук 1: вопрос, поиск, ответ со ссылками на ПУЭ.
- `docs/notebooks/stage5_experiments_notebook.ipynb` - ноутбук 2: таблица и графики по шагам, сравнение с V2.

## 5. Что нового по сравнению с V2

1. **Точное извлечение пункта по номеру.** Номер из вопроса (например, «п. 1.8.16») ищется в `metadata.Clause`, найденный пункт ставится первым. Номера таблиц и рисунков («таблица 1.7.5») не считаются номерами пунктов. В BM25 номер вида 1.7.82 - один токен, а не три числа.
2. **Русская морфология в BM25.** Слова приводятся к основе стеммером Snowball (`snowballstemmer`), запасной вариант - лемматизация `pymorphy3`.
3. **Длинные фрагменты.** Реранкер BGE оценивает длинный чанк по окнам 1500 символов с перекрытием 300 и берёт лучшую оценку окна. Корпус и индексы V2 при этом не меняются. Пример проблемы: пункт 1.8.17 длиной 5439 символов в V2 стоял на 3-7 месте.
4. **Сравнимость с V2.** Те же 720 вопросов (`eval_questions_split.json`) и qrels (`eval_qrels_split.json`), метрики считает код V2 (`retrieval_eval.scoring.evaluate`).
5. **RRF по трём выдачам.** BM25, E5 и CLIP сливаются с k = 60, веса задаются в `v3_config.json`.

## 6. Шаги оценки

Каждый шаг добавляет одно изменение, поэтому прирост можно приписать конкретному улучшению.

| № | Шаг | Что проверяется |
|---|-----|-----------------|
| 1 | `bm25` | только BM25 с морфологией |
| 2 | `e5` | только E5, как поиск V2 без реранкера |
| 3 | `e5+rerank+fullchunk` | E5 + BGE по целому чанку, повтор схемы V2 |
| 4 | `bm25_e5` | BM25 + E5, RRF |
| 5 | `bm25_e5+rerank` | + BGE по окнам |
| 6 | `bm25_e5_clip+rerank` | + CLIP в RRF |
| 7 | `bm25_e5_clip+rerank+exact` | + пункт по номеру из вопроса |

Метрики: Hit@1, 3, 5, 10 по фрагментам и по пунктам, MRR@10, nDCG@10, полнота фактов@5. Сводка по всем вопросам и отдельно по частям `development` и `reserved_evaluation` (ключ `--split`).

## 7. Запуск

Зависимости V2 плюс зависимости V3:

```
pip install -r requirements.txt
```

Нужны запущенный Milvus с коллекциями `diplom_v2_e5` и `diplom_v2_clip` и Ollama с моделью `qwen2.5:14b-instruct-q4_K_M` (только для ответа).

### Скрипты PowerShell

Запускаются из любой папки: корень V3 находится сам (`scripts/stage5_eval/_root.ps1`). Дополнительные ключи передаются в Python, например `.\scripts\run_all.ps1 --split development`.

| Скрипт | Что делает |
|--------|-----------|
| `scripts/run_all.ps1` | все 7 шагов оценки |
| `scripts/run_bm25.ps1` | шаг 1: только BM25 |
| `scripts/run_e5.ps1` | шаг 2: только E5 |
| `scripts/run_e5_rerank.ps1` | шаг 3: E5 + BGE по целому чанку |
| `scripts/run_hybrid.ps1` | шаг 4: BM25 + E5, RRF |
| `scripts/run_hybrid_rerank.ps1` | шаг 5: + BGE по окнам |
| `scripts/run_hybrid_clip.ps1` | шаг 6: + CLIP |
| `scripts/run_final.ps1` | шаг 7: + пункт по номеру |
| `scripts/run_dev.ps1` | все шаги, сводка по части `development` |
| `scripts/run_reserved.ps1` | все шаги, сводка по части `reserved_evaluation` |
| `scripts/run_variants.ps1 -Variants bm25,bm25+exact` | выбранные шаги |
| `scripts/run_ask.ps1 -Question "..."` | один вопрос и ответ; `--no-llm` - только поиск |
| `scripts/run_tests.ps1` | проверки без GPU, Milvus и Ollama |

Если PowerShell запрещает запуск скриптов, для текущего окна:

```
Set-ExecutionPolicy -Scope Process Bypass
```

### Python

Из папки V3:

```
python scripts/v3_evaluation.py
python scripts/v3_evaluation.py --variants bm25 bm25+exact
python scripts/v3_evaluation.py --split development
python scripts/v3_ask.py "Что сказано в п. 1.7.82?" --no-llm
python -m unittest discover -s scripts/tests -t . -v
```

Результаты: `V3/results/<запуск>/<шаг>/runs.json`, `metrics.json` и сводка `summary_all.csv` (разделитель «;», десятичная запятая).

## 8. Контрольный прогон BM25

Шаги BM25 не требуют GPU и Milvus и проверены на 720 вопросах:

| Шаг | Hit@1 | Hit@5 | MRR@10 |
|-----|-------|-------|--------|
| BM25 без морфологии | 0,7042 | 0,8903 | 0,7832 |
| BM25 со стеммером Snowball | 0,7417 | 0,9153 | 0,8178 |
| BM25 + пункт по номеру | 0,7458 | 0,9167 | 0,8206 |

Морфология даёт +3,8п.п. Hit@1. Номер пункта есть только в 17 вопросах из 720, поэтому прирост от точного извлечения небольшой. Шаги с E5, CLIP и BGE требуют прогона на GPU.

## 9. Ограничения

- Чанки V2 не перерезаются: окна используются только при переранжировании. Перерезка корпуса требует новых коллекций и относится к V4.
- Диапазоны пунктов («пп. 4.2.123-4.2.132») дают только крайние пункты.
- Неразмеченные пары в qrels получают нулевой зачёт; это не доказанная нерелевантность.
